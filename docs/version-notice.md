# 오픈가든 ERP 새 버전 확인·안전 새로고침 (구현안)

## 구현 내용

- 로그인 후 ERP 사이드바 하단에서 현재 버전과 **업데이트 확인**을 표시한다.
- 5분 간격, 탭 복귀, 네트워크 재연결 시 `/api/app-version`을 확인한다.
- 다른 배포 버전이 발견되면 **새 버전이 준비되었습니다** 알림을 띄운다.
- 사용자가 누르지 않는 한 페이지를 자동으로 새로고침하지 않는다.
- 할 일 입력/수정, 댓글, 일정 생성 등의 **작성 내용이 남아 있거나 저장 진행 중이면** 알림 버튼으로 새로고침하지 못하게 막는다.
- 브라우저 자체 새로고침/닫기 시에도 작성 중이면 기본 확인창을 띄우려 시도한다(브라우저 정책에 따라 표현 다름).
- API 오류나 세션 만료 시에는 자동으로 로그아웃하거나 다시 로그인시키지 않는다.
- 기존 Auth.js/Google 로그인 코드, Airtable 원본 레코드, 견적서·제안서 HTML의 `localStorage` 데이터는 변경하지 않는다.

## 구성 및 파일

- `src/lib/app-release.ts`: 서버 배포 ID 및 사용자에게 표시할 버전 레이블 조회
- `src/app/api/app-version/route.ts`: 세션이 있을 때만 배포 정보 반환, 캐시 금지
- `src/components/update-notice.tsx`: 폴링, 알림, 폼 수정·저장 상태 감지
- `src/components/app-shell.tsx`: 로그인된 ERP 전체 화면에 버전 확인 UI 배치
- `todo-add-form.tsx`, `todo-detail-form.tsx`, `todo-comments.tsx`, `event-composer.tsx`, `todo-status.tsx`: 작업 중 표시 및 저장 완료 후 상태 해제
- `.env.example`: 수동 배포 식별자 및 사용자용 버전 표시 설정 예시

## Vercel 설정

1. Project Settings > Environment Variables > **Automatically expose System Environment Variables** 활성화 여부를 확인한다. 이때 `VERCEL_DEPLOYMENT_ID`가 빌드/런타임에 있어야 한다.
2. `APP_VERSION_LABEL`을 사람이 읽기 쉬운 값(예: `v1.2 · 업데이트 확인`)으로 등록한다. 버전을 바꿀 때는 레이블도 변경한다.
3. Vercel이 시스템 환경변수를 제공하지 않는 호스팅 환경에서는 배포할 때마다 `APP_RELEASE_ID`를 새로운 고유 문자열로 바꾼다. 같은 값을 재사용하면 알림이 뜨지 않는다.
4. 기존 인증 관련 환경변수(`AUTH_*`, `GOOGLE_*`)는 변경하지 않는다.
5. `main`에 덮어쓰기 전에 **최신 GitHub 브랜치에 코드만 병합**하고 Preview 배포부터 검증한다.

## QA 수동 테스트 필수

| 조건 | 기대 결과 |
|---|---|
| v1에 로그인한 상태에서 v2 운영 배포 | 5분 내 또는 재진입 시 알림(배포 라우팅/Skew 설정에 따라 영향) |
| 업데이트 없음 | 현재 버전만 표시, 새로고침 강제 없음 |
| 할 일 입력 중 버튼 선택 | 저장 먼저 안내, 내용 유지 |
| 댓글 작성 중 버튼 선택 | 저장 먼저 안내, 내용 유지 |
| 일정 저장 요청 진행 중 | 저장 완료 전 새로고침 차단 |
| 할 일 수정 후 저장 성공 | 폼의 미저장 상태 해제 |
| 인증 만료 / 오프라인 / API 오류 | 강제 로그아웃·새로고침 없음 |
| 브라우저 홈 화면 바로가기 | 새 배포 알림, 사용자 선택 시 웹 새로고침 |
| 제안서·견적서의 독립 HTML 화면 | **이번 릴리스의 알림 대상이 아님**. 별도 리로드 보호 추후 개발 |

## 한계 및 다음 단계

- *신규 배포 알림*은 클라이언트에서 읽고 작성 중인 내용을 날리지 않도록 하는 장치이지, 자동 저장 기능이 아니다.
- 서버 액션 저장 실패가 보고되면 작성 중 표시를 해제하지 않는다.
- 정상적인 세션 유지 여부는 Auth.js 쿠키 만료와 Google 계정 정책에 좌우되며, 새로고침 자체가 세션을 연장하거나 로그인 상태를 영구 보장하지 않는다.
- `public/tools/proposal.html`, `public/tools/quote.html` 같은 독립 HTML 도구는 현재 별도로 동작하며, 이번 패치의 새 버전 배너 적용 범위에 포함되지 않는다. 변경 없이 유지했다.
- Next.js `router.refresh()`는 페이지 데이터 갱신 기능이므로 새 번들의 JS를 얻기 위해 사용자가 직접 누르는 경우에만 `window.location.reload()`를 사용한다.
- Vercel 배포 라우팅 및 Skew Protection 설정에 따라서 오래 열린 클라이언트가 새 `/api/app-version`에 도달하는지 Preview 배포에서 검증해야 한다.

## 테스트 현황

- 변경 TS/TSX 파일 9개 구문 변환 검사 통과.
- 버전 식별자 로직 및 폼 보호 장치 정적 검사 통과.
- 의존성 캐시 부족(`npm ci --offline` 실패)으로 **Next.js 전체 빌드, 실제 브라우저 E2E, 실운영 검증은 아직 실시하지 못함**.
- 운영 GitHub·Vercel 및 Airtable 데이터에 직접 변경 없음.
